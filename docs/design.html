Anderdingus v0.1 design

Browser version of docs/design.md. Keep the two in sync.

Goal

A Discord bot that answers CS2 players' questions about live game state ("who has the bomb?", "team economy?") from official Game State Integration (GSI) data. It only reads data; it never sends input to the game.

Alpha 0.1: what "done" looks like

One player runs CS2 with a GSI config. In a Discord server they type /bomb, /economy or /round and the bot replies with the right answer from live data. Plain code, no model, all on the owner's PC. A short demo recording is the exit test.

Not in alpha 0.1: multiple players, voice, natural language, any model, callouts, minimap.

Architecture

CS2 gameGSI POST → Receiver
auth + validate→ State store→ Query functions→ Responders→ Discord botManual CLI
  • Event source (receiver): the only part that knows GSI. A vision source can join it later.
  • State store: latest payload plus short history, timestamped.
  • Queries: pure functions over state; easy to test with fixtures; reused by every responder.
  • Responders: Discord and the CLI call the same queries. A model, if any, sits here later and only rephrases or routes.
  • Game adapter: boundary between a game's raw data and normalized state, so other games can plug in.

Testing

Fixtures replay through the real receiver, so the game is not needed for tests. The game is needed twice: to record real payloads and verify the schema, and for the alpha demo.

Sprints

# Name What Exit
1 Pipeline proven Merge first slice. Record real payloads, replace hand-written fixtures, fix schema. Manual replay and ask work on a real recording.
2 Alpha 0.1 Discord bot, three slash commands, one player, local. Needs a Discord bot token. Demo recording.
3 Team state Companion app sends each friend's GSI to the bot with player identity; merge into team state. Team economy and bomb across the team.
4+ Later Model decision and natural language, callouts, voice, minimap spike. Decided per item.

Open questions

  • Model: rules only, local model, or paid API. Parked until GPU is known.
  • Networking for sprint 3: bot runs on the owner's PC, so friends need a safe route to it (private network tool or tunnel).
  • GSI limits: each player reports only their own state, so team features need every friend running the companion.

Integrity

Only data a player could legitimately see or that teammates share. No automated input. Public or tournament use needs a per-game, per-platform rules check first.
